# 页脚 i18n 补齐

日期：2026-10-04 · 影响：页脚（统计行 + 来源标签）、caption 路径

## 症状

用户问「页脚的 i18n 没做？」。查下来页脚三处没跟随用户语言：

| 位置 | 问题 |
| --- | --- |
| 来源标签 | **硬编码英文** `f"Source（{display}）"`，16 个语言全都显示英文 |
| 点赞数 | 走**模块级 `t_`**（默认语言），而旁边的查看数走调用方的 `_t` → 可能出现「1,455 表示 · 158 likes」 |
| 日期 | 只有 `zh` 用「年月日」，日语也用年月日书写习惯，却显示 `2026-10-04` |

## 改动

1. **来源标签**：源码字面量改成 `来源（{display}）`（兜底 `来源`），两个渲染路径
   （`build_caption_by_str`、`build_rich_markdown`）都按 `lang` 取译文；
   `build_caption_by_str` 新增 `lang` 参数（此前它拿不到语言）。
2. **点赞**：`t_("点赞")` → `t_[lang]("点赞")`；`build_metadata_line` 的兜底同样按 `lang`。
3. **日期**：`lang.startswith(("zh", "ja"))` 都用「年月日」。

i18n 词条（键 = `md5(源码字面量)[:12]`，字典序插入）：

- `0a87f26596ed` = `来源（{display}）`
- `26ca20b161c3` = `来源`

16 个语言文件全部补齐，例如 `Source ({display})`（英文用半角括号）/ `ソース（{display}）` /
`Источник ({display})` / `แหล่งที่มา ({display})`。

## 遗留（未做，待定）

**平台名不翻译**：`来源（酷安）` 在英文界面下仍是中文平台名。平台名是专有名词，
保留原名是惯例（Twitter/Pixiv 也是原名），但中文平台名（酷安 / 豆瓣 / 抖音 / 快手 / 微博 / 小红书）
是否该给英文名（Coolapk / Douban / Douyin / Kuaishou / Weibo / RED）尚未定。等用户决定。

## 排错备注

探针若自己传 `view_label="查看"`（中文字面量），会盖掉 i18n 兜底，看起来像「查看没翻译」——
**生产调用方传的是 `_t("查看")`（已翻译）**，不是 bug。核对 i18n 时别传字面量。
