# 转发动态的 `//@` 原文不再丢弃

日期：2026-10-04 · 影响：bilibili 转发动态（引用块内容）

## 症状

用户问：**「这个为什么丢了 `//@夏日幻听MCE:10月新番《#脑洞学生会！#》第1话 已更新！` 这些内容？」**

## 根因

`_strip_forward_comment` 把它剥掉，**依据的假设是"原文会由引用块重新渲染，留着就重复"**。
这个假设对**视频分享**不成立：

| 来源 | 内容 |
| --- | --- |
| `//@` 段（主动态 desc） | `10月新番《#脑洞学生会！#》第1话 已更新！` ← 原动态的**正文** |
| 引用块（来自 `orig.archive`） | 视频**标题** `「脑洞学生会！」第1话【中文字幕】` + **简介** `「脑洞学生会！」第1话` |

两段文字**不是一回事**，实测在引用块纯文本里搜 `已更新` = False → 内容确实丢了。

## 改动

- `_strip_forward_comment` → **`_split_forward_comment`**：返回 `(转发者的话, //@ 段原文)`，
  不再丢后者（顺带剥掉 `原作者:` 前缀）。
- `_render_forward(forward, extra_text=...)`：原文并进引用块，**排在视频信息之前**。
- **去重**：`_forward_text_is_covered()` 在归一化（去空白/标点/`#`/零宽字符）后比较，
  原文已被 title/简介覆盖时跳过 —— 纯文字动态的转发不会显示两遍。

```
> 夏日幻听MCE：                                  ← UP 主页链接
> 10月新番《 #脑洞学生会！ 》第1话 已更新！         ← //@ 段原文（本次找回）
> 「脑洞学生会！」第1话【中文字幕】                ← 视频标题 → 视频页链接
> 「脑洞学生会！」第1话                          ← 视频简介
```

## 验证

- lib 415 passed（新增 3 条：原文进引用块 / 重复跳过 / 归一化去重）、bot 271 passed、ruff 全过。
- 真机：content 含 `已更新` = **True**（修复前 False）；服务端块 `RichBlockBlockQuotation` 内含 4 行。

## ⚠️ 缓存

parser 改动会固化在缓存 content 里 —— 已用 `CacheRepo.remove_by_keys` 清掉 3 条（含这条 url）。

## 备注（未改）

原文里的 `#脑洞学生会！#` 经 `hashtag_handler` 输出成 ` #脑洞学生会 `（前后补空格），
于是书名号里成了 `《 #脑洞学生会！ 》`。这是 `hashtag_handler` 的既有行为（主动态正文同样如此），
本次未动。
