# bgm 话题页脚：emoji 状态数 + 回复数

日期：2026-10-07

用户问：「抓 html 能拿到 emoji 状态数（总和）和回复数吗，可以就放页脚」。

## 数据来源：页面内联的脚本（**不需要额外请求**）

```js
var data_likes_list = {"411450":{"140":{"type":10,"main_id":41209,"value":"140",
                                        "total":6,"emoji":"101","users":[...]}},
                       "411451":{"54":{...,"total":2,"emoji":"15","users":[...]}}};
```

- 按**楼层 id** 组织，每层若干 emoji
- `total` = **贴这个表情的人数** —— 实测与 `users` 数组长度逐一对齐（6/6、2/2），
  所以它是人数，**不是** emoji 种类数
- `likes_grid_<post_id>` 只是**空容器**（JS 填充），数据只能从脚本取

**回复数**页面上没有现成字段 ⇒ 由楼层数派生。

## 口径

| 项 | 口径 |
| --- | --- |
| 状态数 | 话题内**所有楼层**的 emoji 状态 `total` **之和**（人数求和）|
| 回复数 | **楼层总数 − 1**（主楼不算回复；楼中楼算一条）|

页脚形态：`2026年10月5日 14:14 · 8 状态 · 8 回复 · 来源（Bangumi）`

## 落点

- **状态数走 `like_count` 位**：bgm 没有"点赞"，它的表情回应才是同一种正反馈；
  文案由 `plugins/helpers.metadata_like_label` 按平台给（bgm → 「状态」，其余仍「点赞」）
- **回复数是通用字段** `ParseResult.reply_count`（多数平台都有这个概念），
  渲染层"拿不到就不显示"（不预留位置），与前两条计数同一原则
- **0 要显示**："0 回复"有信息量（没人回复 ≠ 拿不到）；判据是 `None`（拿不到）与 `0` 分开

## 验证

真机三条（生产容器、完整流水线）：

| 链接 | 页脚 |
| --- | --- |
| `/subject/topic/41209`（主楼）| `… 8 状态 · 8 回复` |

| `/group/topic/472394` | `… 13 状态 · 52 回复` |

统计是**整帖**的 —— 分享哪一层都一样（页脚说的是话题的规模）。
与取证时的算式一致（6 + 2 = 8）。

## 教训

**页面上"看起来是空壳"的容器，数据可能在旁边的内联脚本里**。
`likes_grid_<id>` 是空的（JS 填充），但 `data_likes_list` 就在同一页 ——
先 dump 整个 HTML 找脚本变量，别看到空 div 就下"拿不到"的结论。
（日志页那次相反：`likes_grid_<id>` 与 `/like/list/...` 都是空壳，所以日志拿不到状态数。）
