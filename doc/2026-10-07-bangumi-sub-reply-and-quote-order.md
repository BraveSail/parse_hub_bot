# bgm 楼中楼：引用父楼 + 引用块放最前

日期：2026-10-07

用户在一个链接上提了两件事：

> https://bgm.tv/rakuen/topic/subject/41119#post_410747 第一，这个是楼中楼，如何处理，
> 第二，刚才说的行间距，图片和引用贴一起了

## 一、楼中楼引用**父楼**，不是主楼

`#4-1`（sakuyo）是**纯图回复**（正文为空、1 张图），它在 DOM 上嵌在 **`#4` 层**的
正文容器里（`post_410733` 的 `topic_reply_410733`）⇒ 它回复的是 **`#4`**。

而引用块当时一律用**主楼**（`_quote_of(opening)`）—— 对**一级楼层**是对的
（它们确实回复主楼），对**楼中楼**是答非所问。

**改**：`BangumiFloor` 记 `parent_dom_id`（DOM 上最近的 `post_<id>` 祖先，收集子楼时
本来就在父楼的遍历里，顺手记下）；`_build` 里楼中楼用**父楼**当引用块，一级楼层不变。

父楼不在页面上（被删）时记 warning 并退回主楼 —— 坏数据不该让整条解析失败。

## 二、图片和引用块贴一起：引用块的位置决定媒体落在哪一侧

渲染层 `parts` 的顺序是 `[body, media, quote]` —— **媒体永远在「末尾引用块」之前**
（那是**推特**的语义：主推自己的媒体在上面、引用卡片在下面）。

而 `split_quote_blocks(content)` 是**按位置**分块的：开头 → `reply_quote`，末尾 → `quote`。

bgm 原来的产物是「归属行 + 引用块」：

- **有正文**时引用块在中间 → 媒体排在最后 ✓ 没问题
- **纯图楼层**（本层无文字）引用块落到**末尾** → 图被插到它**前面**、贴在一起 ✗

**改**：产物改成「**引用块在最前** + 归属行 + 本层正文」（与 linux.do 同形态 ——
上下文引用块在前、本层内容在后）。引用块进 `reply_quote` 通道，媒体自然跟在它后面。

验证（真机渲染顺序）：

| 情形 | 渲染顺序 |
| --- | --- |
| `#4-1`（纯图楼中楼）| [引用块 #4] → [归属行] → [图片] |
| `#4`（一级楼层）| [引用块 #1] → [归属行] → [图片] |

## 教训

**引用块的"位置"是有语义的**：它决定媒体落在引用块的哪一侧。本层内容要排在引用块
后面，引用块就**必须是产物第一块**；元信息行（归属/来源）不要挡在它前面 ——
挡住了它就进不了"被回复卡片"那条通道。

真机实测的排布对照（服务端块结构）：

| 写法 | 结果 |
| --- | --- |
| `> 引用` + 空行 + 图 | `BlockQuotation` + `Photo`（两块，分开）|
| `> 引用` + 图（无空行）| `BlockQuotation` 内嵌 `Photo`（图被吸进引用块）|
| 图 + 空行 + `> 引用` | `Photo` + `BlockQuotation`（图在引用块上方）|
