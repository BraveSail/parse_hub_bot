# 图片与引用卡片之间的一行间距

日期：2026-10-07

用户报：「图片和引用贴在一起」（最初我理解成"引用与正文之间"，用户纠正：**是图片**）。

## 为什么"加个空行"做不到

真机实测（同一条消息文本、读回服务端块结构）：

| 写法 | 块结构 |
| --- | --- |
| ``块 + 空行 + 正文`` | `BlockQuotation` + `Paragraph` |
| ``块 + **两个**空行 + 正文`` | **完全相同**（连续空行被折叠）|
| ``块 + 半角空格段 + 正文`` | **完全相同**（半角空格段被丢弃）|
| ``块 + **全角空格**段 + 正文`` | `BlockQuotation` + **`Paragraph 　`** + `Paragraph` ✓ |
| ``块 + `---` + 正文`` | `BlockQuotation` + `Divider` + `Paragraph`（有间距但是条线）|

能产出独立块的有两种：**全角空格段落**（纯间距）与 **`---` 分割线**。

先用了全角空格 —— 用户反馈「**这个不行太宽了，试试分割线**」，于是改成分割线。
实现为 `plugins/helpers.py` 的 `_QUOTE_GAP = "---"`。

⚠️ 别改成半角空格、空行或空串 —— 都会被折叠，间距直接消失，且**没有任何报错**。

## 插在哪

只在**引用卡片与图片相邻**时插（两个方向都要）：

- 卡片在前、图片在后 —— bgm 的纯图楼层（引用层 + 本层的图）
- 图片在前、卡片在后 —— twitter（主帖的图 + 末尾的引用卡片）

判据用两段内容本身：卡片 = ``> …`` 或 ``<blockquote>`` 开头；媒体块 = ``![]`` 或
``<tg-collage>`` 开头。

**卡片内部的图不插** —— ``> ![](…)`` 是卡片的一部分，加了间距它就掉出卡片，
变成卡片外面的独立图片块。实测 linux.do 的楼层（图在卡片内）间距数为 **0** ✓。

## 验证

真机三条（生产容器、完整流水线）：

| 场景 | 产物里的间隔位置 |
| --- | --- |
| bgm 纯图楼层 | `> 引用内容` 与 `![](图)` **之间**是一条 `---` |
| twitter 引用带图 | `![](图)` 与 `> 引用卡片` **之间**是一条 `---` |
| linux.do 楼层（卡内图）| **没有间隔** —— 图在卡片内部 |

服务端对 `---` 的渲染已实测为独立的 `Divider` 块。

测试：`test/test_quote_media_gap.py`（9 项：两个方向、只插一段、卡内图不插、
无图不插、不相邻不插、回退路径同样有间距）。bot 538 / lib 723。

## 教训

**富文本的空白是服务端说了算的** —— "多打几个空行"在 markdown 里是排版意图，
在富文本里会被规范化掉。需要**确定的一行间距**时只能找一个能产出独立块的字符
（全角空格），并且**用读回块结构的方式验证**，不能靠"我写了空行所以应该有间距"。
